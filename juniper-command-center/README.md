## What works

**Operations / Profit & Scale:** a shared synthetic business with eight branches, 60 technicians and 3,451 generated work orders over 15 weekdays. The financial engine calculates branch and consolidated revenue, contribution, operating profit, staffing capacity, data eligibility and configurable scenario comparisons. Aggregate capacity planning is not equivalent to a feasible appointment schedule.

**Mathematical optimization:** `lab/advanced.py` uses real Google OR-Tools CP-SAT on a bounded subset (up to 40 jobs and 12 technicians). It enforces skill eligibility, branches, shift/time windows, stock limits, no overlapping work and synthetic inter-job travel times. It reports actual solver status and compares results with a reproducible greedy baseline. It is not a whole-network live GPS or VRPTW product. The historical exact-enumeration subset remains in `lab/engine.py` for continuity.

**Strategic Program:** four initiatives, dependency precedence, a day-level shared technical-resource schedule, seeded Monte Carlo projections and constrained investment allocation. CRM and workforce adoption are mandatory; discretionary benefits use documented overlapping-benefit adjustments. Budget, staffing and adoption assumptions can change.

**Service Command:** deterministic fictional incident replay plus an optional **server-side structured LLM connector** in `lab/llm.py`. The `lab/llm_evaluate.py` harness contains 35 developer-authored reference cases. **No actual LLM benchmark has been executed or claimed without authorized credentials.** Models can interpret notes but never authorize a database write themselves.

**Approved synthetic execution:** a local FastAPI service, SQLite incident/appointment tables, server-validated bearer tokens, approved transitions, idempotency keys, optimistic appointment versions, audit records and baseline reset. An approved supported change updates the persisted synthetic appointment's status. There is no public writable API or real third-party CRM connection.

The **public Decision Lab** recalculates aggregate financial and investment outputs in JavaScript using branch inputs generated by `lab/web_export.py` from the Python source. CP-SAT, Monte Carlo risk simulations, optional LLM calls and SQLite transactions run **locally**, not from the GitHub Pages browser.

## Reproduce locally

Python 3.11 or higher. From `juniper-command-center/`:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pytest -q
python -m lab.generate --out data/juniper_synthetic_v1.json
python -m lab.web_export
python -m lab.evaluate
python -m lab.reporting --out /tmp/juniper-reports
uvicorn lab.api:app --reload
```

Browse `http://127.0.0.1:8000/docs`. The API offers `/api/scenario`, `/api/branches`, `/api/program`, `/api/optimize`, `/api/portfolio`, `/api/interpret`, `/api/incidents`, `/api/appointments/{order_id}`, state-transition and audit routes. OpenAPI contains request schemas.

### Local privileged workflow

Configure **private** tokens using your shell environment, not JavaScript, query parameters or committed files:

```bash
export JUNIPER_MANAGER_TOKEN="replace-with-your-own-long-random-manager-token"
export JUNIPER_DISPATCHER_TOKEN="replace-with-your-own-long-random-dispatch-token"
# Windows PowerShell: $env:JUNIPER_MANAGER_TOKEN="replace-with-your-own-long-random-manager-token"
```

Create a fictional incident with an Authorization bearer header using the dispatcher token, then approve and execute with the manager token and the expected current version:

```bash
curl -X POST http://127.0.0.1:8000/api/incidents \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $JUNIPER_DISPATCHER_TOKEN" \
  -d '{"note":"Appointment #44 needs rescheduling","incident_id":"training-example-1"}'
```

Follow with POST `/api/incidents/training-example-1/transition` and body `{"action":"approve","expected_version":1}` then `{"action":"execute","expected_version":2}`, with the **manager** bearer token. Inspect `GET /api/appointments/WO-01-0044` and `/api/incidents/training-example-1/audit`. `POST /api/reset` requires manager authentication and restores the synthetic baseline.

The legacy `X-Role` header **does not** grant any permission in the current API. Local bearer tokens are a bounded demo control, not a full enterprise identity/tenancy system.

### Optional LLM mode

Set `OPENAI_API_KEY` only in the server environment. `POST /api/interpret` with `"live":true` requires manager authorization and applies a bounded local-process request limit; `"live":false` runs deterministic replay. To execute the **35-case real-model evaluation** intentionally:

```bash
python -m lab.llm_evaluate --live
```

This uses provider credits and is **not** part of ordinary CI. Without credentials the integration's validation logic and fallback run, while empirical LLM metrics remain unavailable.

## Modeled economics

The three synthetic recurring service fees are $145/$255/$345 before deterministic price variation; fully burdened labor is $27.50/hour, travel $0.26/minute, and material cost $11/$24/$43 by service type. Fixed branch expense is $850 per weekday. Only completed simulated jobs generate recognized revenue. Contribution = revenue less direct materials, service labor and travel; operating profit = contribution less branch fixed costs. Neither is labeled EBITDA or cash flow.

Synthetic dataset version: `2026.10.v1`, seed `20261014`. Current **application** release: `2026.10.v2`. Earlier Juniper Vale sample datasets and workbooks are preserved as separate historical exercises.

## Release process

Ordinary `.github/workflows/juniper-tests.yml` runs with **read-only** repository permission and never commits generated outputs. The controlled `.github/workflows/juniper-release.yml` validates then publishes a matching source ZIP, browser dataset, test output and the two reports in **one release commit**, when explicitly requested. PDF and ZIP outputs can be regenerated from source without a commercial service.

The core engineering release is reproducible without paid hosting or a model subscription. Synthetic appointment performance, simulated project risk, and assumed financial returns are not historical client results.
