# Juniper Vale architecture | 2026.10.v2

## One modeled business
A fixed-seed generator (`20261014`) creates eight branches, 60 technicians, 1,200 customers, 15 weekdays, 3,451 work orders and completed-job invoices. Unique identifiers and relationships are validated. `lab.engine.DATA` underpins finance, program and synthetic incident decisions. Scenario assumptions are explicit and deterministic, with `scenario_id` and `data_version` returned by `integrated()`.

## Profit & Scale decision engine
`lab/engine.py` calculates branch contribution from completed services less direct burdened labor, materials and travel; operating profit subtracts fixed branch cost once. Company P&L is the sum of branch statements. Aggregate capacity is a **planning approximation**. `lab/advanced.py` contains a bounded Google OR-Tools **CP-SAT** solver that enforces technician skills, branch, time windows, shift length, stock, nonoverlapping assignments and inter-job travel proxy. The independent `validate_assignments` method checks output constraints. `greedy_baseline` runs on the same records for comparison. This is not live GPS or whole-region VRPTW.

## Strategic Program
Four initiatives: CRM modernization, dispatch optimization, AI service operations and adoption standards. The scheduler enforces finish-start dependencies and a shared technical-staff pool, detects cycles and blocks CRM cutover if modeled quality is below 95%. Fixed-seed Monte Carlo risk uses independent triangular durations and explicitly excludes empirical correlations. `investment_allocation` enumerates feasible mandatory/discretionary portfolios under budget, technical resources, dependencies and adoption assumptions. Discounted NPV uses synthetic benefit estimates with overlap adjustments; expected benefits are not earned savings.

## AI and synthetic transactions
`lab/llm.py` optionally calls a provider from the **server**, accepts JSON-schema output, validates grounded references and forces human review on ambiguous or hostile input. A deterministic replay remains the default and has separate evidence. `lab/llm_evaluate.py` contains 35 synthetic reference cases; without a permitted model execution, **no empirical LLM accuracy or latency is claimed**.

`lab/security.py` checks server-configured long bearer tokens and maps them to viewer, dispatcher and manager roles. It **does not** trust the old `X-Role` header. Public access is read-only. In `lab/workflow.py`, SQLite transactions protect the sequence Pending Review → Approved/Rejected → Executed → Resolved; execution checks current version, allowed action, source work order, CRM release quality, and approval, then updates the synthetic appointment row and audit event atomically. Duplicate incident keys and stale records are rejected; manager-authorized reset restores baseline. This is a controlled **local demonstration**, not authenticated enterprise tenancy.

## Public delivery boundary
GitHub Pages hosts `web/index.html` and `web/data.json`. The latter is generated by `lab/web_export.py` from the canonical Python model. The browser recalculates aggregate operations and constrained investment selections for visitors; it does not expose Python, SQL or provider keys. A separate original `transformation-lab.html` historical scenario replay is retained for continuity. The live Python FastAPI service, OR-Tools scheduling, report generation, risk analysis and controlled CRM transactions are reproducible **locally**.

## Testing and release
Ordinary CI tests a fixed checkout with **read-only** permissions: pytest, synthetic generation, browser JavaScript syntax, browser source/model reconciliation and PDF signatures. It uploads evidence and makes **no commits**. A separate explicitly requested controlled release builds the latest source ZIP, regenerated browser inputs, test summary and two reports, then commits them as one matching release. Production systems, a hosted writable API, road-network routing and an empirically measured live LLM evaluation are outside this synthetic portfolio release.
